Context for the owner: upstream `main` (dc7cb6c6, fetched 2026-09-29) still
spawns a new `claude --resume` process for every chat message. Two open PRs
address the duplicate process: #1395 stops the old process's background tasks
before the new turn starts (work is lost), and #1431 keeps one process per
conversation and pushes the next message into it (work survives). Our fork
adopted #1431 unchanged and added four fixes on top. The text below reports
those four fixes to the #1431 author.

---

Thanks for this. I ran #1431 on a self-hosted install that hit the duplicate
process described in #1325 and #884. I measured that problem first, then
tested the PR against it. Four things came up. Each has a regression test
that fails or hangs on the PR head (`d84f8425`) and passes with the patch
below.

**Root cause, measured on 1.37.3 with CLI 2.1.281.** When the next message
arrives, `queryClaudeSDK` releases the held stdin first. After that,
`addSession` calls `interrupt()`, but the SDK drops control requests written
to an ended stdin (`ProcessTransport.write`: "Dropping write to ended stdin
stream"). The promise rejects only when that query is cleaned up much later.
That is why every supersede logs `Error interrupting superseded run …: Query
closed before response received`. Our log shows it at 13:17:49, 13:33:27 and
13:36:43, each time when an old process finally exited. After EOF the CLI
keeps waiting for its background agents and runs the turns their
notifications trigger. Two processes then drove one transcript for about
7 minutes, and both resumed the same agent ids.

**1. `queryClaudeSDK` no longer settles until the process exits.** With the
process kept alive after every turn, the promise stays pending until the
30-minute idle timeout. Three callers await it to finish their own work:
`git.routes.ts` (AI commit message: the HTTP request hangs), `agent.routes.ts`
(the external agent API: the branch/PR step and the response wait), and the
scheduled-message dispatcher. Patch: the exported function resolves when its
own turn completes. The process loop continues in `runClaudeProcess`.

**2. Runs without an app session id idle for nothing.** Commit-message
generation passes no `sessionId`. Nothing can address that process again, yet
it stayed up for 30 minutes with all its MCP servers. On our box that is about
450 MB for the CLI plus about 1.2 GB for 14 MCP children. Patch:
`scheduleRelease` releases stdin at once when there is no `sessionId`.

**3. The restart path waits on `processClosed` with no bound, and ignores an
abort.** If the idle CLI does not exit on EOF (a slow hook or MCP shutdown),
the user's edited message hangs. If the user presses Stop during that wait,
`abortClaudeSDKSession` completes the run, but the restart still spawns a new
CLI and runs the turn the user just cancelled. Patch: wait up to 10 s, then
`close()`. Skip the spawn when the session was aborted in the meantime.

**4. Abort after stdin has ended hangs on the dropped interrupt.** This is the
same SDK behaviour as the root cause. `abortClaudeSDKSession` awaits
`interrupt()` before its `finally` closes the query. When stdin is already
closed (restart wind-down, idle release), that await lasts until the process
exits on its own. Patch: `LiveSession.inputOpen()`. Interrupt only while
stdin is open, then close as before.

One existing PR test had to change: "automatic untracked activity renews the
lease and exit cancels it" used `await done` as a signal that the process had
exited. With fix 1, `done` settles with the turn, so the test now waits for
`script.released()`.

**Live check, real CLI.** We ran a second instance with the patch. Turn 1
started `sleep 60` with `run_in_background`. Turn 2 was sent 3 s after turn 1
completed. The background completion then arrived as an automatic turn on the
turn-2 stream. A 1-second `ps` sampler saw one PID for the whole run (107
samples). The server logged `Starting async generator loop` exactly once.

Tests: `server/modules/providers/tests/claude-one-process.test.ts`. Its fake
CLI models the three behaviours above: EOF ends stdin; after EOF the CLI stays
up while background work is outstanding; an interrupt after EOF is dropped.
Full backend suite: 600 tests, 599 pass, 1 skipped, with `CLAUDE_CLI_PATH`
unset (4 path tests fail when it is inherited, on `main` too).

Patch: branch `homelab/one-process` on https://github.com/raum01/claudecodeui.
